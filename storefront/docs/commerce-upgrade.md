# راهنمای تحویل فروشگاه‌ساز — آبان ۱۴۰۵

## استفاده از manager

از بخش «فروشگاه‌ساز»، یک image جدید `storefront-api:v20261119-commerce-2` و یکی از ۱۶ قالب را انتخاب کنید. رنگ برند مستقل از قالب است. ساخت فروشگاه همچنان منابع اختصاصی همان نمونه، migration، بررسی سلامت و اتصال nginx را طی می‌کند. فهرست قالب‌ها از `catalog.json` خوانده می‌شود؛ تست Go تطابق آن را با renderer کنترل می‌کند. برنچ جدیدی ساخته نشده است.

نمونهٔ مستقل: `http://shopdemo.localhost`، پنل فروشنده: `/seller` و پنل توسعه‌دهنده: `/admin`. شمارهٔ فروشندهٔ دمو `+989120000002` و شمارهٔ ادمین دمو `+989120000001` است. در حالت دمو کد یک‌بارمصرف روی صفحه نمایش داده می‌شود؛ پیامک و پرداخت واقعی انجام نمی‌شود. سفارش‌ها، تعرفه‌ها، نظر و درخواست بازگشت آزمایشی برچسب دارند. نمونهٔ قبلی `shoptest` در manager تعلیق شده بود؛ سیاست آن تغییر نکرده است.

## امکانات قابل تنظیم توسط مالک

| بخش | رفتار |
| --- | --- |
| محصول | برند، ضمانت، وزن بسته، گالری، جدول مشخصات، تنوع مستقل و SKU |
| تنوع | رنگ و نام رنگ، سایز، نمونه‌رنگ قابل انتخاب، تصویر مخصوص، قیمت جاری و قبلی، موجودی و تعدیل موجودی |
| ارسال و تحویل | پست/شرکت حمل، پیک یا دریافت حضوری؛ تعرفه، حداقل خرید، آستانهٔ رایگان، سقف وزن، استان/شهر و بازهٔ تخمینی روز تقویمی |
| سفارش | هزینه و شرایط تحویل از سرور، یادداشت مشتری، ثبت حمل‌کننده و کد رهگیری، وضعیت دریافت حضوری و پیگیری در حساب مشتری |
| CMS | صفحهٔ مستقل با پیش‌نویس و انتشار، منوی دلخواه، بنر، متن، مزایا و FAQ؛ ترتیب و فعال‌بودن بخش‌ها |
| ترب | روشن/خاموش‌کردن دریافت کاتالوگ، توکن خصوصی وبهوک، آدرس API و sitemap، تعداد محصولات در صف و آخرین پذیرش وبهوک |
| نظرات | ثبت فقط پس از خرید پرداخت‌شده و تحویل‌شده، انتشار یا پنهان‌کردن توسط فروشنده، نمایش نظر تأییدشده در صفحهٔ محصول |
| بازگشت | درخواست مشتری، تأیید/رد با پاسخ فروشگاه، ثبت دریافت کالا و بستن رسیدگی با ثبت نتیجه |

شرایط و هزینهٔ تحویل در سفارش snapshot می‌شود؛ تغییر تعرفهٔ بعدی مبلغ سفارش قبلی را تغییر نمی‌دهد. checkout استان و شهر را از نشانی واقعی می‌گیرد. تعرفهٔ غیرمجاز، غیرفعال یا متعلق به شهر دیگر پذیرفته نمی‌شود. بازه‌ها تخمینی و روز تقویمی هستند؛ ساعت قطع پذیرش، تعطیلات و SLA زندهٔ شرکت حمل در این محاسبه وارد نمی‌شوند.

تغییر موجودی محصول موجود همچنان به‌شکل delta ذخیره می‌شود تا خرید هم‌زمان با ویرایش، موجودی را بازنویسی نکند. حذف تنوع از ویترین، رکورد موجودی موردنیاز سفارش‌های قبلی را حذف نمی‌کند.

## قرارداد اتصال ترب

فروشنده باید دامنهٔ عمومی را در پنل ترب ثبت کند و نشانی‌های زیر را به پشتیبانی بدهد:

```text
https://<store-domain>/torob_api/v3/products
https://<store-domain>/sitemap.xml
```

API با `POST application/json`، هدرهای `X-Torob-Token` و `X-Torob-Token-Version: 1` و کلید رسمی Ed25519 ترب کار می‌کند. امضا، الگوریتم، audience، انقضا، not-before و نسخه بررسی می‌شوند. مسیر فقط برای این درخواست امضاشده از محدودیت Origin مرورگر مستثناست؛ کنترل Host و سایر مرزهای CSRF پابرجاست.

حالت‌های درخواست: `page_urls`، `page_uniques`، صفحه‌بندی ۱۰۰تایی با `date_added_desc` و `date_updated_desc`، و cursor با `product_id_desc`. پارامتر ناقص یا متناقض خطا می‌گیرد. خواندن feed از query صفحه‌بندی‌شدهٔ دیتابیس انجام می‌شود و محدود به ۵۰۰ محصول ویترین قدیمی نیست. محصول غیرفعال و تنوع حذف‌شده خروجی ندارد. قیمت feed تومان است؛ هستهٔ محاسبات همچنان ریال صحیح است.

هر تنوع `page_unique` ثابت، `product_group_id` مشترک و پیوند `?variant=<id>` دارد. صفحهٔ مقصد همان تنوع را انتخاب می‌کند؛ قیمت/تصویر/موجودی متاتگ‌های SSR نیز مربوط به همان تنوع است. دادهٔ ساختاریافتهٔ `ProductGroup` و `hasVariant` خروجی دارد.

برای اطلاع‌رسانی سریع، توکن وبهوک دریافتی از ترب را در پنل ذخیره کنید. توکن در دیتابیس رمزگذاری و در خروجی عمومی ماسک می‌شود. triggerهای دیتابیس تغییر محصول، قیمت و رزرو/آزادسازی موجودی را در صف ماندگار می‌گذارند. lease، retry با backoff و مقایسهٔ generation مانع گم‌شدن تغییر هم‌زمان می‌شوند. محدودکنندهٔ مشترک دیتابیس فاصلهٔ حداقل ۴ ثانیه میان ارسال‌ها را بین replicaها حفظ می‌کند. پذیرش وبهوک فقط پذیرش برای پردازش است؛ تضمین نمایش یا تأیید فروشگاه در ترب نیست.

## قالب‌ها و طراحی

۱۰ خانوادهٔ قبلی حفظ شده‌اند و پالت‌های متمایز دارند. شش خانوادهٔ جدید: مد (`mode`)، زیبایی (`bloom`)، دیجیتال (`volt`)، سوپرمارکت (`fresh`)، کودک (`little`) و دست‌ساز (`craft`). این‌ها چیدمان، نسبت تصویر، کارت و نمایش موبایل متفاوت دارند. عنوان و تصویر اصلی از محتوا قابل ویرایش است. تصاویر و محصولات دمو نمونه هستند؛ مالک تصاویر مرتبط با کسب‌وکار خودش را بارگذاری می‌کند.

منابع بررسی‌شده در ۱۹ نوامبر ۲۰۲۶:

- [Torob Product API v3](https://github.com/torob/Torob-Sync/blob/main/product_api_v3.md)، [JWT](https://github.com/torob/Torob-Sync/blob/main/torob_api_token_guide.md)، [وبهوک](https://github.com/torob/Torob-Sync/blob/main/product_webhook.md): قرارداد مستقیم اتصال.
- [Baymard: Checkout UX](https://baymard.com/research-articles/current-state-of-checkout-ux) و [بازهٔ تحویل](https://baymard.com/research-articles/shipping-speed-vs-delivery-date): شفافیت هزینه، انتخاب تحویل و اطلاعات سفارش.
- [Google Product Variants](https://developers.google.com/search/docs/appearance/structured-data/product-variants): شناسهٔ گروه، تنوع و URL قابل انتخاب.
- [IKEA](https://www.ikea.com/us/en/)، [Gymshark](https://www.gymshark.com/) و [Apple Store](https://www.apple.com/store): بررسی الگوهای کشف دسته، ویترین تصویری و عرضهٔ محصول؛ لوگو یا دارایی اختصاصی این برندها کپی نشده است.
- [Effective Go](https://go.dev/doc/effective_go): قالب‌بندی و قواعد زبان؛ مرزبندی لایه‌ها علاوه بر آن با تست معماری پروژه کنترل می‌شود.

## بررسی و ارتقا

```sh
make storefront-check
make storefront-integration
make manager-check
STOREFRONT_SMOKE_HOST=shopdemo.localhost make storefront-smoke
STOREFRONT_SMOKE_HOST=shopdemo.localhost make storefront-commerce-smoke
make storefront-release NAME=<existing-store> IMAGE=storefront-api:v20261119-commerce-2
```

دو migration افزایشی، تاریخ ایجاد محصولات، صف همگام‌سازی، نظرات و درخواست‌های بازگشت را اضافه می‌کنند. integration در schema جدا اجرا و rollback می‌شود؛ تست feed با ۵۰۷ محصول، کنترل تعرفه و شهر، snapshot سفارش، رمزگذاری توکن، generation صف، نظر تأییدشده و چرخهٔ بازگشت را بررسی می‌کند. smoke دمو عمداً دادهٔ آزمایشی می‌سازد.

مرزهای عملیاتی: صدور بارنامه و نرخ زندهٔ شرکت حمل نیازمند قرارداد و API ارائه‌دهنده است. بستن پروندهٔ بازگشت بازپرداخت بانکی یا افزایش موجودی انجام نمی‌دهد؛ تسویه و بازرسی واقعی باید جدا انجام شود. اتصال واقعی ترب، پیامک و درگاه به دامنهٔ عمومی، اطلاعات پذیرندگی و تأیید ارائه‌دهنده نیاز دارد. تست‌های این تحویل پول یا پیامک واقعی ارسال نکرده‌اند. مالیات، حسابداری، چندانبار و اتصال ERP جزو این نسخه نیستند؛ پروژه همچنان وابستگی Mizan ندارد.

# Deploying this project on the shared server infrastructure

This project runs on a server that already provides **shared** PostgreSQL (behind PgBouncer), Redis,
RabbitMQ, an edge nginx, and an OpenTelemetry/Prometheus/Tempo/Grafana stack. This project must
**use** them, not start its own. Read this whole file before touching Dockerfiles, compose files,
config or telemetry code. Everything below is a rule unless it says "optional".

## What the infrastructure gives you

| Need | How the project reaches it (inside Docker network `infra`) | Provided via env var |
|---|---|---|
| PostgreSQL 18 | host `pgbouncer`, port `5432` (transaction pooling, never connect to Postgres directly) | `DATABASE_URL` |
| Redis 8 | host `redis`, port `6379`; ACL user limited to keys `<app>:*` | `REDIS_URL`, `REDIS_KEY_PREFIX` |
| RabbitMQ 4 | host `rabbitmq`, port `5672`; own vhost + user | `AMQP_URL` |
| Traces + metrics | OTLP to `otel-collector`, gRPC `4317` / HTTP `4318` | `OTEL_EXPORTER_OTLP_ENDPOINT` + `OTEL_*` |
| Public HTTP | the shared nginx routes `Host` header -> your container (TLS is terminated at the ArvanCloud CDN; the server speaks plain HTTP) | n/a |

All of these values are generated by the infra owner (`scripts/new-project.sh <app> ...` on the server)
into `/srv/apps/<app>/.env` **on the server**. Never invent, hardcode or commit credentials; read
every setting from the environment. The project needs an `.env.example` listing the variable names.

## Hard rules

1. **Image names**: `<app>-<service>:<tag>` (e.g. `shop-api`, `shop-web`). Tag = git SHA. Never `latest`.
2. **Unique service names.** All projects share one Docker network, and a service name is its DNS name.
   Two projects with a service called `api` would round-robin each other's traffic. Prefix **every**
   compose service with the app name (`shop-api`, `shop-web`, `shop-worker`). Names `postgres`,
   `pgbouncer`, `redis`, `rabbitmq`, `nginx`, `otel-collector`, `prometheus`, `grafana`, `tempo` are reserved.
3. **Do not publish ports** (`ports:` is forbidden). nginx reaches containers over the `infra` network.
4. **No state inside the container.** Run with `read_only: true`. Uploads/persistent files go to a bind
   mount under `/srv/data/apps/<app>/` (owned by uid 65532); scratch space is `tmpfs: [/tmp]`.
5. **Resource limits are mandatory** on every service (`mem_limit`, `cpus`). The server has 4 cores and
   8 GB shared with ~15 other containers; an unlimited container can take the whole box down.
6. **Run as non-root** (uid 65532), `cap_drop: [ALL]`, `security_opt: [no-new-privileges:true]`.
7. **No dependency on infra start order.** Retry DB/Redis/RabbitMQ connections with exponential backoff
   at startup and after disconnects. Compose `depends_on` cannot reach across projects.
8. **Logs go to stdout/stderr as JSON** (one object per line, include `trace_id` when a span is active).
   Do not write log files. Do not export OTLP logs (there is no log backend; `OTEL_LOGS_EXPORTER=none`).
9. **Config only via environment variables.** The same image must run anywhere.
10. **Expose `GET /healthz`** returning 200 when the process is alive (do not check dependencies in it).
    It is used by Docker healthchecks and by external uptime probes.

## Go services

### Dockerfile (static binary, `scratch` final image, runs as 65532)

`REGISTRY` defaults to the Arvan mirror because Docker Hub is not reliably reachable; override with
`--build-arg REGISTRY=docker.io` if needed.

```dockerfile
# syntax=docker/dockerfile:1
ARG REGISTRY=docker.arvancloud.ir
ARG GO_VERSION=1.24
FROM ${REGISTRY}/golang:${GO_VERSION}-alpine AS build
WORKDIR /src
COPY go.mod go.sum ./
RUN --mount=type=cache,target=/go/pkg/mod go mod download
COPY . .
RUN --mount=type=cache,target=/go/pkg/mod --mount=type=cache,target=/root/.cache/go-build \
    CGO_ENABLED=0 GOOS=linux GOARCH=amd64 \
    go build -trimpath -ldflags="-s -w" -o /out/api ./cmd/api

FROM scratch
COPY --from=build /etc/ssl/certs/ca-certificates.crt /etc/ssl/certs/
COPY --from=build /usr/share/zoneinfo /usr/share/zoneinfo
COPY --from=build /out/api /app/api
USER 65532:65532
EXPOSE 8080
ENTRYPOINT ["/app/api"]
```

`scratch` has no shell or curl, so the binary implements its own health probe:
`/app/api healthcheck` must do `GET http://127.0.0.1:8080/healthz` and exit 0/1.

### Runtime settings

* `GOMEMLIMIT` = ~85% of `mem_limit` (set in compose, e.g. `mem_limit: 256m` -> `GOMEMLIMIT=215MiB`).
* `GOMAXPROCS`: import `go.uber.org/automaxprocs` (or use Go >= 1.25, which is cgroup-aware).
* Handle `SIGTERM`: stop accepting, drain in-flight requests (<= 10 s, the compose stop grace period),
  flush OpenTelemetry providers, close pools, exit.
* Listen on `0.0.0.0:8080` (plain HTTP).

### PostgreSQL (through PgBouncer, transaction pooling)

* Use `pgx` / `pgxpool`; take `DATABASE_URL` from env. Suggested pool: `MaxConns=20`, `MinConns=2`,
  `MaxConnLifetime=30m`, `MaxConnIdleTime=5m`, `HealthCheckPeriod=1m`. (PgBouncer multiplexes client
  connections onto ~10 server connections per database, so extra client connections are cheap.)
* Transaction pooling means **no session state**: no `SET` (use `SET LOCAL` inside a transaction),
  no session-level advisory locks (`pg_advisory_xact_lock` is fine), no `LISTEN/NOTIFY`, no temp tables
  across statements, no `WITH HOLD` cursors.
* Protocol-level prepared statements work (PgBouncer `max_prepared_statements` is on); pgx defaults are fine.
* Set per-query timeouts with `context.WithTimeout` (30 s default). The DB role has a 40-connection cap.
* **Migrations**: use a tool that does not rely on session-level advisory locks (goose, atlas, tern with
  locking disabled). golang-migrate's lock is session-level and unsafe through PgBouncer. Run migrations
  as a separate one-shot step/command of the same image (`/app/api migrate`), not inside every replica boot.
* The infra owner can reach Postgres directly on the server at `127.0.0.1:5432` (SSH tunnel) for admin tasks.

### Redis

* `go-redis`: `redis.ParseURL(os.Getenv("REDIS_URL"))`.
* **Every key must start with `REDIS_KEY_PREFIX`** (e.g. `shop:`). The ACL rejects other keys.
  Pub/Sub channels must use the same prefix.
* **Every cache key needs a TTL.** The server evicts only keys that have a TTL (`volatile-lru`); a key
  without TTL is never evicted, and when memory is full, writes fail. Data that must not expire belongs
  in PostgreSQL, not Redis.
* Forbidden by ACL: `KEYS`, `FLUSHALL`, `FLUSHDB`, `CONFIG`, `DEBUG`, `SHUTDOWN` and other admin/dangerous
  commands. Use `SCAN` with a prefix instead of `KEYS`.
* Single logical DB (`/0`); isolation is by prefix + ACL, not by DB number.

### RabbitMQ

* `github.com/rabbitmq/amqp091-go`, `AMQP_URL` from env (already includes the vhost).
* One connection per process, one channel per goroutine/consumer (channels are not goroutine-safe).
* Declare queues/exchanges `durable`; use **publisher confirms** for important messages; consumers use
  manual ack with `Qos(prefetch 10-50)`; dead-letter failed messages instead of requeue-looping.
* Handle `NotifyClose`: reconnect with backoff and re-declare topology.
* Vhost limits: 100 connections, 500 queues. Keep message size small (< 1 MB); store blobs elsewhere.

### OpenTelemetry (traces + metrics)

* Export **OTLP gRPC** to `OTEL_EXPORTER_OTLP_ENDPOINT` (already `http://otel-collector:4317`).
  Read service name/attributes from env (`OTEL_SERVICE_NAME`, `OTEL_RESOURCE_ATTRIBUTES` are provided
  or set in compose); do not hardcode them.
* **Sampler: `ParentBased(AlwaysSample)`.** Sampling is done by the collector (keeps all errors, all
  traces slower than 1 s, and a percentage of the rest). Do not head-sample in the SDK.
* Propagators: W3C `TraceContext` + `Baggage`. nginx forwards `traceparent`, so traces continue across hops.
* Instrument: `otelhttp` (HTTP server -> metric `http.server.request.duration`, which feeds the
  "Applications" Grafana dashboard), `otelpgx` or `pgx` tracer for queries, `redisotel` for Redis, and
  runtime metrics (`go.opentelemetry.io/contrib/instrumentation/runtime`).
* Metric reader interval 30 s. Use bounded label values only (never user IDs, URLs with IDs, raw errors).
* Put `trace_id` / `span_id` into JSON logs so a log line can be matched to its trace in Grafana.
* Flush on shutdown (`tp.Shutdown(ctx)`, `mp.Shutdown(ctx)`).

Minimal setup:

```go
func initTelemetry(ctx context.Context) (shutdown func(context.Context) error, err error) {
    res, err := resource.New(ctx, resource.WithFromEnv(), resource.WithTelemetrySDK(), resource.WithHost(), resource.WithProcess())
    if err != nil { return nil, err }

    te, err := otlptracegrpc.New(ctx) // endpoint/protocol from OTEL_EXPORTER_OTLP_*
    if err != nil { return nil, err }
    tp := sdktrace.NewTracerProvider(
        sdktrace.WithBatcher(te),
        sdktrace.WithResource(res),
        sdktrace.WithSampler(sdktrace.ParentBased(sdktrace.AlwaysSample())),
    )

    me, err := otlpmetricgrpc.New(ctx)
    if err != nil { return nil, err }
    mp := sdkmetric.NewMeterProvider(
        sdkmetric.WithReader(sdkmetric.NewPeriodicReader(me, sdkmetric.WithInterval(30*time.Second))),
        sdkmetric.WithResource(res),
    )

    otel.SetTracerProvider(tp)
    otel.SetMeterProvider(mp)
    otel.SetTextMapPropagator(propagation.NewCompositeTextMapPropagator(propagation.TraceContext{}, propagation.Baggage{}))
    _ = runtime.Start() // go.opentelemetry.io/contrib/instrumentation/runtime

    return func(ctx context.Context) error { return errors.Join(tp.Shutdown(ctx), mp.Shutdown(ctx)) }, nil
}
```

### Behind the CDN and the shared nginx

* TLS ends at ArvanCloud; the app only speaks HTTP. Never redirect to https yourself based on the
  connection; use the `X-Forwarded-Proto` header (nginx always sets it) to decide whether a request was
  HTTPS (secure cookies, absolute URLs).
* Client IP: use the `X-Real-IP` header (nginx sets it to the real visitor address). Trust it only
  because the app is reachable only through nginx.
* CDN caching: serve static assets with `Cache-Control: public, max-age=31536000, immutable` (hashed
  filenames); HTML with `no-cache`; authenticated or personalised API responses with `private, no-store`.
  Do not compress responses yourself (nginx/CDN do).
* Uploads larger than 20 MB are rejected by nginx; talk to the infra owner if you need more.
* CORS: if the client and API are on different domains, the API must send the proper CORS headers.

## Client (frontend) container

Static SPA built in Docker, served by an unprivileged nginx on port 8080 (the shared nginx proxies to it):

```dockerfile
ARG REGISTRY=docker.arvancloud.ir
FROM ${REGISTRY}/node:22-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM ${REGISTRY}/nginxinc/nginx-unprivileged:alpine   # verify this tag exists on the mirror
COPY nginx.conf /etc/nginx/conf.d/default.conf        # listen 8080; try_files $uri /index.html; long cache for hashed assets
COPY --from=build /app/dist /usr/share/nginx/html
```

Run it with the same compose hardening as the API (`read_only: true` plus `tmpfs: [/tmp, /var/cache/nginx]`).
If the client is server-rendered (SSR) it is just another container listening on a port.

## Compose file for production: `deploy/compose.yaml`

The image tag comes from `${TAG}` (set by the ship script). `env_file: .env` is the server-side file
generated by the infra owner (path is relative to the compose file on the server).

```yaml
name: shop                      # = APP name
services:
  shop-api:
    image: shop-api:${TAG}
    env_file: [.env]
    environment:
      OTEL_SERVICE_NAME: shop-api
      GOMEMLIMIT: 215MiB
    volumes:
      - /srv/data/apps/shop/uploads:/data/uploads
    mem_limit: 256m
    cpus: 1.0
    read_only: true
    tmpfs: [/tmp]
    user: "65532:65532"
    cap_drop: [ALL]
    security_opt: ["no-new-privileges:true"]
    restart: unless-stopped
    stop_grace_period: 15s
    logging: { driver: json-file, options: { max-size: "10m", max-file: "3" } }
    healthcheck:
      test: ["CMD", "/app/api", "healthcheck"]
      interval: 10s
      timeout: 3s
      retries: 3
      start_period: 15s
    networks: [infra]

  shop-web:
    image: shop-web:${TAG}
    mem_limit: 64m
    cpus: 0.5
    read_only: true
    tmpfs: [/tmp, /var/cache/nginx]
    cap_drop: [ALL]
    security_opt: ["no-new-privileges:true"]
    restart: unless-stopped
    logging: { driver: json-file, options: { max-size: "10m", max-file: "3" } }
    healthcheck:
      test: ["CMD-SHELL", "wget -q -O /dev/null http://127.0.0.1:8080/ || exit 1"]
      interval: 10s
      timeout: 3s
      retries: 3
    networks: [infra]

networks:
  infra:
    external: true
```

Add a `shop-worker` service the same way for background consumers (it also needs `networks: [infra]`).
Services that only talk to each other and not to the shared infra can use a private network instead.

## Shipping (build locally, deploy over SSH, no registry)

The ship script lives in the infra repo (`scripts/ship.sh`); copy it into the project as
`scripts/ship.sh`. The project provides `ship.conf` at its root:

```bash
APP=shop                                     # must match the name given to new-project.sh
SSH_HOST=deploy@my-server
COMPOSE_FILE=deploy/compose.yaml
IMAGES=("api=./backend" "web=./client")      # service=context[:dockerfile] -> image shop-api, shop-web
```

`scripts/ship.sh` builds `linux/amd64` images locally, tags them with the git SHA, streams them to the
server with `docker save | ssh | docker load`, runs `docker compose up -d --wait`, and **rolls back to
the previous tag automatically** if the new containers do not become healthy. Commit before shipping
(a dirty tree gets a `-dirty<timestamp>` tag).

## First-time onboarding (needs the infra owner, once per project)

1. Choose the app name (`^[a-z][a-z0-9-]{1,30}$`) and the domains. Each project has its own domains.
2. Infra owner runs on the server (inside the infra repo):
   `scripts/new-project.sh <app> --client-domain app.example.com --client-upstream http://<app>-web:8080 --api-domain api.example.com --api-upstream http://<app>-api:8080`
   (or `--api-path /api` to serve the API under the client's domain). This creates the database, Redis
   user, RabbitMQ vhost, nginx server blocks, uptime probes, and `/srv/apps/<app>/.env`.
3. Point the domains in the ArvanCloud panel at the server IP (HTTP origin, port 80).
4. `scripts/ship.sh` from the developer machine.

## Checklist before opening a PR

- [ ] Dockerfile builds a static binary and runs as uid 65532; `/app/<bin> healthcheck` works
- [ ] Every compose service is prefixed with the app name, has `mem_limit` + `cpus`, healthcheck,
      `read_only`, `cap_drop: [ALL]`, `no-new-privileges`, joins only `infra`, publishes no ports
- [ ] All config from env vars; `.env.example` lists them; no secrets committed
- [ ] DB access through `DATABASE_URL`, no session state; migrations are PgBouncer-safe
- [ ] Redis keys prefixed with `REDIS_KEY_PREFIX` and have TTLs; RabbitMQ queues durable with reconnect logic
- [ ] OTel: OTLP gRPC to the collector, `ParentBased(AlwaysSample)`, `otelhttp` on the server, trace IDs in logs
- [ ] Graceful shutdown on SIGTERM; startup retries with backoff for DB/Redis/RabbitMQ
- [ ] `GET /healthz` exists and does not depend on external services
- [ ] `ship.conf` present; image names are `<app>-<service>`

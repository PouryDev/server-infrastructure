# وصل کردن دامنه‌ی آروان‌کلاد به یک پروژه

این راهنما مراحل دستی است. هیچ‌چیزش خودکار نیست و هیچ توکنی لازم ندارد.

مسیر ترافیک: `کاربر ──HTTPS──▶ CDN آروان (TLS تمام می‌شود) ──HTTP :80──▶ nginx سرور ──▶ کانتینر پروژه`.
یعنی SSL فقط روی آروان است و روی سرور گواهی لازم نیست.

## قبل از شروع

1. IP عمومی سرور را داشته باش (همان که آروان باید به آن وصل شود).
2. پروژه روی سرور ساخته شده باشد، یعنی `make new-project` را با دامنه‌ی درست زده باشی. این دستور دو چیز می‌سازد:
   - `config/nginx/conf.d/<پروژه>.conf` با `server_name <دامنه>;`
   - probe آپتایم در `config/prometheus/targets/http-probes.yml`

   اگر دامنه را بعداً می‌خواهی، بخش «تغییر دامنه» پایین را ببین.
3. پورت ۸۰ سرور از اینترنت باز باشد (یا فقط برای IPهای آروان، بخش «قفل کردن روی CDN»).

## مرحله ۱: دامنه را به آروان اضافه کن

۱. در پنل آروان، بخش CDN، دامنه را اضافه کن.
۲. nameserverهای ثبت‌کننده‌ی دامنه (جایی که دامنه را خریده‌ای) را به nameserverهایی که آروان نشان می‌دهد عوض کن.
۳. صبر کن تا وضعیت دامنه در آروان **فعال** شود. تا فعال نشده بقیه‌ی مراحل اثری ندارد.

## مرحله ۲: رکوردهای DNS

برای هر نام زیر یک رکورد **A** بساز. ابر (پروکسی) باید **روشن** باشد.

| نام | مقدار (IP) | پورت | ابر (پروکسی) | ارتباط CDN با سرور |
|---|---|---|---|---|
| `@` (خود دامنه) | IP سرور | `80` | روشن | **HTTP** |
| `www` | IP سرور | `80` | روشن | **HTTP** |
| `api` (اگر API دامنه‌ی جدا دارد) | IP سرور | `80` | روشن | **HTTP** |

نکات:

- «ارتباط CDN با سرور = HTTP» مهم‌ترین تنظیم است. nginx سرور گواهی ندارد و اگر روی HTTPS بماند، آروان خطای ۵۲x می‌دهد.
- رکورد `www` را حتماً بساز، حتی اگر کسی مستقیم نمی‌زندش، چون ریدایرکت مرحله ۴ به آن نیاز دارد.
- اگر API روی همان دامنه‌ی اصلی زیر `/api` است، رکورد جدا لازم نیست (`--api-path` در `new-project`).
- اگر `api.example.com` زیر همان zone دامنه‌ی اصلی است، رکوردش را در همان zone بساز. اگر دامنه‌ی مستقل است، آن را جداگانه در آروان اضافه کن و همین مراحل را برایش تکرار کن.

## مرحله ۳: SSL

در بخش SSL/TLS همان دامنه:

۱. SSL را **فعال** کن.
۲. گواهی را از نوع **مدیریت‌شده توسط آروان (managed)** بگذار، نه گواهی دستی.
۳. صبر کن تا گواهی صادر شود (چند دقیقه). وضعیت سفارش گواهی را در همان صفحه می‌بینی.
۴. اختیاری ولی پیشنهادی: **تغییر مسیر HTTP به HTTPS** را روشن کن تا کاربری که `http://` زده خودکار به `https://` برود.
۵. اختیاری: حداقل نسخه‌ی TLS روی `TLSv1.2` و HSTS فقط بعد از اینکه مطمئن شدی همه‌چیز با HTTPS کار می‌کند.

## مرحله ۴: ریدایرکت www به دامنه‌ی اصلی

در تنظیمات دامنه، گزینه‌ی تغییر مسیر www را روی **«www به دامنه‌ی اصلی» (root)** بگذار.
نتیجه: `https://www.example.com/...` همیشه به `https://example.com/...` می‌رود.

محدودیت: این گزینه در سطح zone است و فقط `www.<zone>` را به `<zone>` می‌برد.

- برای `www.example.com` درست کار می‌کند.
- برای `www.api.example.com` (وقتی api زیر zone دیگری است) کار نمی‌کند. اگر لازمش داری، یا api را دامنه‌ی مستقل بگیر، یا ریدایرکتش را در nginx بنویس (رکورد `www.api` + یک `server` با `return 301 https://api.example.com$request_uri;`).

## مرحله ۵: بررسی

```bash
# 1) DNS به آروان اشاره می‌کند (IP خود آروان را می‌دهد، نه IP سرور)
dig +short example.com

# 2) HTTPS کار می‌کند و ریدایرکت www درست است
curl -sI https://example.com/ | head -n 5
curl -sI https://www.example.com/ | grep -i -E "^HTTP|^location"
#   انتظار: 301 و location: https://example.com/

# 3) سالم بودن API
curl -s https://api.example.com/healthz
```

اگر خطا گرفتی:

| علامت | علت محتمل |
|---|---|
| خطای ۵۲x یا ۵۰۲ از آروان | «ارتباط CDN با سرور» روی HTTPS مانده یا پورت ۸۰ سرور بسته است. روی HTTP و پورت ۸۰ بگذار. |
| صفحه‌ی پیش‌فرض nginx یا ۴۰۴ | `server_name` در `config/nginx/conf.d/<پروژه>.conf` با دامنه یکی نیست. |
| گواهی نامعتبر | گواهی هنوز صادر نشده، یا SSL فعال نیست، یا رکورد پروکسی‌شده نیست (ابر خاموش است). |
| ریدایرکت حلقه شد | `https_redirect` در آروان روشن است و برنامه هم خودش به https ریدایرکت می‌کند. فقط یکی از آن‌ها. |
| IP کاربر در لاگ همیشه IP آروان است | `make update-arvan-ips` را بزن تا realip به‌روز شود. |

## قفل کردن روی CDN (پیشنهادی)

تا وقتی پورت ۸۰ برای همه باز است، هر کس IP سرور را پیدا کند می‌تواند CDN را دور بزند.

```bash
make update-arvan-ips     # لیست IPهای آروان و تنظیم realip nginx را تازه می‌کند
make firewall             # اول dry-run نشان می‌دهد، بعد با تأیید اعمال می‌شود
```

## تغییر دامنه‌ی یک پروژه

دامنه‌ی جدید را اول در آروان بساز (مراحل ۱ تا ۴ برای دامنه‌ی جدید)، بعد روی سرور:

```bash
cd ~/projects/infrastructure/server-infrastructure

# 1) nginx: دامنه‌ی قدیمی را با جدید عوض کن
sed -i 's/old\.example\.com/new.example.com/g' config/nginx/conf.d/<پروژه>.conf
make nginx-test && make nginx-reload

# 2) probe آپتایم
sed -i 's#https://old\.example\.com#https://new.example.com#g' config/prometheus/targets/http-probes.yml
make prometheus-reload
```

بعد از اینکه دامنه‌ی جدید جواب داد، رکوردهای دامنه‌ی قدیمی را در آروان پاک کن.
اگر پروژه خودش دامنه را در تنظیمات دارد (CORS، آدرس مطلق، کوکی)، همان‌ها را هم به‌روز کن.

## دامنه‌ی محلی (`.localhost`)

`<پروژه>.localhost` و `api.<پروژه>.localhost` فقط روی همین ماشین کار می‌کنند و به آروان ربطی ندارند. probeهای آپتایم برای آن‌ها `https://` می‌زنند و شکست می‌خورند؛ هشدار `EndpointDown` را نادیده بگیر.
